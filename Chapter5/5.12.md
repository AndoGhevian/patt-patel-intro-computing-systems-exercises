### 5.12 After executing the following LC-3 instruction: ADD R2, R0, R1, we notice that R0[15] equals R1[15], but is different from R2[15]. We are told that R0 and R1 contain UNSIGNED integers (that is, nonnegative integers between 0 and 65,535). Under what conditions can we trust the result in R2?

We can trust the result always except when there is overflow happen, because ADD instruction even though operate on 2's complement integers, performs the addition as simple binary
addition with carry.

But here, what is happening in one situation can be valid in another invalid.

1. if R0[15] and R1[15] are 0 and then result is 1, there is no
unsigned overflow happen, it is ok.

2. if they are both 1 and then result has most significant bit 0,
then obviously number becomes smaller, so it gives overflow,
so we cant trust it.
