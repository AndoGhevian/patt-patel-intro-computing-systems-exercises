### 7.17

LABEL usage is ok in each module, given
it is a symbolic name of some instruction
or data in a corresponding module which is
referenced explicitely in a program.

In each such case assembler will replace label
with appropriate memory offset agains LC.

Pseudo-op .EXTERNAL is required in case if
label does not identified in a program in the
first pass through it while creating symbol table.

In such case .EXTERNAL is required to not
lead to error of not finding symbolic name in
a symbol table while translating isntruction
using that label in it to reference the memory.

Well, ok, book answer is more precise:

if we want to use same label in different
modules for different addresses, it is completly
ok -> different modles fit in different addresse
range.

But if we want to use label for the same location
in different modules, we should use .EXTERNAL
pseudo op in the module that refere to memory
in other module, to leave address resolution
for that not identified label to linker.
